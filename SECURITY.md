# Security Policy

## Reporting a Security Issue

Do not report security vulnerabilities through public GitHub Issues.

If you discover a security vulnerability:

1. Do not disclose the vulnerability publicly.
2. Contact the repository owner or security administrator privately.
3. Include a clear description of the vulnerability.
4. Include steps to reproduce the issue where possible.
5. Allow the team time to investigate and respond.

## Sensitive Information

Never commit sensitive information to the repository, including:

- Passwords
- API keys
- Access tokens
- Private keys
- Credentials
- `.env` files containing secrets

Use approved secret-management solutions for sensitive values.

## Security Review

Repository owners should periodically review:

- Repository access
- Team permissions
- Outside collaborators
- Branch protection rules
- Secrets and credentials
- Security alerts and dependency findings

## Access Principle

Access should follow the principle of least privilege. Users should receive only the permissions necessary to perform their responsibilities.
