# Contributing Guidelines

Thank you for contributing to this project.

## Branch Naming

Use clear and descriptive branch names.

Examples:

- `feat/<ticket>-short-name`
- `fix/<ticket>-short-name`
- `chore/docs-update`

## Development Workflow

1. Create a new branch from `main`.
2. Make the required changes.
3. Commit changes with a clear commit message.
4. Push the branch to GitHub.
5. Open a pull request into `main`.
6. Request review from the appropriate team.
7. Address review comments if required.
8. Merge only after required approvals and checks pass.

## Pull Request Guidelines

- Keep pull requests focused on one change.
- Provide a clear title and description.
- Link the related issue or ticket when applicable.
- Do not merge directly into `main` when branch protection requires a pull request.
- Resolve review comments before merging.

## Commit Message Examples

- `feat: add user authentication`
- `fix: resolve login validation issue`
- `docs: update deployment instructions`
- `chore: update repository configuration`
